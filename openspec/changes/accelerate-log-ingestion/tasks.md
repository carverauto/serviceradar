- [x] 2.1a Make `strip_full_message` remove the field. Nulling a top-level field removes nothing, because Zen deletes the null from the rule's result and the overlay keeps the old value. ## 3. Binary and consumers
- [ ] 3.1 Specify metadata fields and complete OTLP/JSON field parity. OTLP protobuf rows now fill observed_timestamp, trace_flags, event_name, source_ip and scope_attributes like JSON rows (#6699). The collector decides the columns OTLP has no field for (`source`, `source_ip`, the service columns) and the syslog wrong-clock time fallback, and sends the columns as `serviceradar.column.*` attributes that only its subject may set; only the collector and an edge leaf carrying an edge collector's batches may publish that subject. Shared cases in `rust/flowgger/tests/resources/normalized_log_parity.json` hold both paths to the same row. Still open: `serviceradar.record_id`, `serviceradar.source_id`, `Sr-Collector-Id`, `Sr-Normalization-Version` and `Sr-Routing-Epoch`, deferred until something reads them (routing is partitioned).
- [ ] 3.1a Decide whether Zen rules configured for `logs.otel` should apply to protobuf OTLP logs. Today they do not: protobuf is that subject's format and is stored without rules. Applying them means running Zen on every OTLP log.
- [x] 3.2 Implement byte/count/age batches with fixed retry bytes and one route/ruleset. The NATS output closes a batch at 256 records, 256 KiB or 100 ms by default, never mixes rulesets, and retries the bytes and message ID it first sent.
- [ ] 3.3 Adapt dual-format EventWriter consumption preserving all required side effects. EventWriter reads collector-normalized OTLP batches from `logs.normalized.<kind>` without running Zen again, requires `Sr-Log-Schema: otlp-normalized-v1`, records `Sr-Ruleset-Id`, and never reads JSON there. Only the log collector's NATS user, and an edge leaf carrying an edge collector's batches, may publish that subject. Protobuf is refused on every other `logs.` subject except `logs.otel`, so switching format cannot skip a subject's rules. Stored-row parity with the producer is checked by the shared cases. Still open: promotion and service-catalog side effects compared on a deployment.
- [ ] 3.4 Verify persistence-before-ACK, partial failure/replay and StarRocks/CNPG parity.
- [ ] 3.5 Roll readers before opt-in producers; verify legacy retained-message draining.

- [ ] 5.3 Hegel: for any decoded syslog record, the record the collector hands its rules equals the record JSON mode publishes.
- [ ] 5.4 Hegel: for any sequence of records, rulesets and limits, the batches hold every record once and in order, never mix rulesets, and stay within the byte limit unless one record exceeds it; every batch decodes to exactly its records.

- [ ] 5.6 Hegel: for any sender time and receive time, the stored time is the sender's or the receive time, and the fallback attributes are present exactly when it is the receive time.
