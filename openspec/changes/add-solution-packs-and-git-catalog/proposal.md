# Change: Add Solution Packs, Catalog Gallery, Signed Release Repositories, and Two-Way GitOps Sync

## Why

ServiceRadar operators author and operate monitoring logic across four separate surfaces today: declarative service and posture checks (`add-declarative-service-and-posture-checks`), alert and normalization rules (`StatefulAlertRule`, `EventRule`, and `ZenRule`), authored dashboards (`ServiceRadarWebNG.Dashboards.Authored`), and optional Wasm plugins (`ServiceRadar.Plugins.PluginPackage`). Because each artifact is created, exported, and seeded independently, there is no portable, secret-free unit for shipping a complete monitoring solution -- such as Storage Entitlements and NVR Recording Health, WAN SLA synthetics, or BGP/SNMP posture -- together with its check graphs, alert rules, dashboards, typed operator parameters, and documentation.

Three concrete platform gaps prevent repeatable sharing across environments (`dev -> staging -> prod`) and across third-party or customer repositories:

1. **No full-stack package contract or secret-free export boundary.** Individual rule and dashboard exports do not bundle `DeclarativeCheck` DAGs, typed `config` inputs, or abstract `credential_slots`, and operators lack a single deterministic archive (`.srpack`) or clean Git directory layout (`packs/<slug>/...`) guaranteed free of plaintext/ciphertext credentials and instance-local UUIDs.
2. **No `RuleSeeder`-style managed upgrade path for multi-resource solutions.** `ServiceRadar.Observability.RuleSeeder` reconciles hardcoded Elixir rule templates at boot using `managed`, `template_version`, and `template_fingerprint`, while `authored-dashboards` leaves existing slugs untouched on re-import. Operators installing a versioned solution pack need a guided install wizard that binds local `NetworkCredentialSecret` / `NetworkCredentialRule` records and saves typed parameter values in `parameter_overrides`, plus a deterministic upgrade workflow (`0.1.0 -> 0.2.0`) that updates upstream check graphs, rules, and dashboards while preserving operator threshold and schedule overrides.
3. **No catalog gallery or pure-HTTPS two-way GitOps workflow.** `ServiceRadar.Plugins.PluginRepository` (`add-third-party-plugin-repositories`) introduces per-repository ed25519 `UploadSignature` verification and AshCloak-backed PAT references for Wasm plugin releases, but operators still lack a searchable Catalog / Solution Packs gallery in `web-ng` (comparable to `demos.timeplus.com` / `timeplus-io/apps`) as well as a way to push and pull secret-free pack trees directly against private GitHub, GitLab, or Gitea repositories over `ServiceRadar.HTTP.EgressClient` without shelling out to host `git` binaries or writing SSH keys to pod disks.

## What Changes

- **Full-stack Solution Pack format (`pack_format_version: 1`) in Git directory tree and `.srpack` archive forms**:
  - Standardizes a deterministic directory layout (`manifest.json`, `README.md`, `checks/*.json`, `rules/*.json`, `dashboards/*.json`, `assets/*`) and deterministic `.srpack` archive (`tar.zst` primary, `.zip` accepted on upload/import) with sorted entries, normalized `0644` permissions, epoch `0` mtimes, and a signed SHA-256 file digest table in `manifest.json`.
  - `manifest.json` declares reverse-DNS `id` (for example `io.serviceradar.storage-and-nvr-health`), `name`, SemVer `version`, `author`, `categories`, inline/data-URI SVG `icon`, `description`, `min_serviceradar_version`, typed `config` parameters (`key`, `type`, `default`, `min`, `max`, `enum`, `required`, `description`), abstract `credential_slots` (`slot`, `provider`, `role`, `purpose`, `required`), optional `plugin_dependencies` (verified Wasm plugin package IDs and SemVer constraints), and deterministic SHA-256 `files` entries.
  - `rules/*.json` templates cover `StatefulAlertRule`, `EventRule`, and `ZenRule` normalization definitions and support per-rule `install_state: "enabled" | "paused"` so high-sensitivity detection rules can ship paused for operator review before activation.
  - Enforces a hard secret-free guarantee on pack build, browser export, and GitOps push: allowlist serialization strips instance UUIDs, strips `credential_secret_id` / `credential_rule_id` bindings in favor of abstract `credential_slots`, and rejects secret-bearing keys or token literals before any archive or Git blob is produced.
- **Guided Install Wizard, `credential_slots` binding, and `RuleSeeder`-style managed upgrades**:
  - Adds `platform.installed_solution_packs` (`ServiceRadar.Catalog.InstalledSolutionPack`) tracking installed `pack_id`, `pack_version`, source provenance, bound `credential_slots`, resolved `config` values, and per-resource installation records.
  - Extends `DeclarativeCheck` (shared contract with `add-declarative-service-and-posture-checks`), `StatefulAlertRule`, `EventRule`, `ZenRule`, and authored `Dashboard` resources with uniform pack provenance and reconciliation attributes: `pack_id`, `pack_version`, `managed`, `template_fingerprint`, and `parameter_overrides`.
  - Adds a guided install and upgrade flow in `web-ng` that collects typed `config` values, binds each required `credential_slot` to CNPG `platform.network_credential_secrets` or `platform.network_credential_rules` (with an inline link to create a missing credential in Settings -> Credentials), verifies optional `plugin_dependencies`, previews every check/rule/dashboard action, and reconciles upgrades (`0.1.0 -> 0.2.0`) while preserving `parameter_overrides`. Editing a managed check's structural DAG prompts the operator to either save a parameter override or detach/fork (`managed: false`).
- **Built-in Pack #1 (`io.serviceradar.storage-and-nvr-health`)**:
  - Packages the first-party Storage Entitlements and NVR Recording Health posture checks (`storage.entitlement_utilization`, `storage.hold_pin_pressure`, `storage.archive_credential_and_usage_health`, `camera.continuous_recording_silence`), companion `StatefulAlertRule` templates, and overview authored dashboard under `priv/solution_packs/storage-and-nvr-health/` using the exact same `pack_format_version: 1` loader and reconciler.
- **Catalog / Solution Packs Gallery UI in `web-ng`**:
  - Adds a dedicated LiveView gallery (`/catalog` and `/settings/catalog`) with full-text search, category filter pills (`Storage & NVR`, `Network & WAN`, `Synthetic HTTP`, `Security & Posture`, `Infrastructure`), inline sanitized SVG icons, "What's inside" badges (`N checks * M alert rules * K dashboards`), rendered `README.md` + architecture/screenshot preview, read-only `@xyflow/react` check DAG + Monaco JSON and upgrade diff viewer, `Installed` vs `Available` tabs, and 1-click `.srpack` / `.json` browser import and secret-free export.
- **Harmonized `CatalogRepository` (`mode: :release_catalog` and `mode: :gitops_tree`)**:
  - Adds `platform.catalog_repositories` (`ServiceRadar.Catalog.CatalogRepository`), harmonized with `ServiceRadar.Plugins.PluginRepository` (`add-third-party-plugin-repositories`): per-repository trust anchors, AshCloak-backed `NetworkCredentialSecret` (`:api_token`) FK with `on_delete: :restrict` registered in `ServiceRadar.Credentials.CredentialUsage` and `GuardCredentialDestroy`, RBAC enforcement, and OCSF audit events via `ServiceRadar.Events.AuditWriter`.
  - **Signed Release Catalogs (`mode: :release_catalog`)**: Seeds official `carverauto/serviceradar` (`builtin: true`, `is_default: true`) and supports both direct HTTPS catalog portal index endpoints (such as `https://developer.serviceradar.cloud/packs/index.json`) and third-party public or private GitHub/Gitea release catalogs serving `serviceradar-pack-index.json` (`index.json`) + `.srpack` + `.sig` assets verified against per-repository ed25519 `UploadSignature` public keys over `ServiceRadar.HTTP.EgressClient` (avoiding public Rekor transparency-log leaks for private repositories).
  - **Two-Way Private Git Tree Sync (`mode: :gitops_tree`)**: Connects private GitHub, GitLab, or Gitea/Forgejo repositories (`repo_url`, `provider_type`, `branch`, `base_path`, `push_strategy: :pull_request | :direct_commit`, and PAT `credential_secret_id`) to push/commit secret-free pack directory trees (`<base_path>/<slug>/...`) and pull/import pack trees across `dev -> staging -> prod` with dry-run diff preview and OCSF audit records, implemented strictly via HTTPS Git Data REST APIs over `ServiceRadar.HTTP.EgressClient` (extending `EgressClient` with bounded non-redirecting `request_json/4` for `POST`/`PUT`/`PATCH`, never shelling out to host `git` or writing SSH keys to pod filesystems).
- **CLI packaging and signing commands in `@carverauto/serviceradar-cli` (`js/cli`)**:
  - Adds `serviceradar-cli pack validate|build|sign|index` (and `serviceradar` bin alias) with byte-for-byte canonical JSON and ed25519 `UploadSignature` parity against `build/wasm_plugins/upload_signature_tool.go` and `ServiceRadarWebNG.Plugins.UploadSignature`.

**BREAKING**: none. Existing standalone `ServiceCheck`, `CompositeCheck`, `DeclarativeCheck`, `StatefulAlertRule`, `EventRule`, `ZenRule`, authored `Dashboard`, and `PluginRepository` records keep `pack_id: nil` and `managed: false` (or existing `RuleSeeder` management) without behavioral change.

## Impact

- **Affected specs**:
  - `solution-packs-catalog` (new capability)
  - `build-web-ui` (Catalog Gallery LiveView, Guided Install/Upgrade Wizard, managed provenance banners/fork prompts, repository & GitOps sync UI)
  - `wasm-plugin-system` (pack `plugin_dependencies` verification and shared `UploadSignature` canonical verification contract)
- **Companion OpenSpec changes**:
  - `add-declarative-service-and-posture-checks` (shares `DeclarativeCheck` canonical JSON schema and exact `credential_slots`, `pack_id`, `pack_version`, `managed`, `template_fingerprint`, and `parameter_overrides` field names)
  - `add-third-party-plugin-repositories` (shares per-repository ed25519 `UploadSignature` verification, `:api_token` `NetworkCredentialSecret` pattern, redirect auth stripping, and RBAC/audit conventions)
  - `add-cli-plugin-publish` (shares `@carverauto/serviceradar-cli` command dispatch and canonical JSON signing conformance corpus)
- **Affected code**:
  - `elixir/serviceradar_core/lib/serviceradar/catalog/` (new `ServiceRadar.Catalog` domain, `CatalogRepository`, `InstalledSolutionPack`, `PackManifest`, `SecretFreeValidator`, `PackArchive`, `Reconciler`, `ReleaseCatalogClient`, `GitOpsTreeClient`, `CatalogNotifier`)
  - `elixir/serviceradar_core/lib/serviceradar/http/egress_client.ex` (bounded non-redirecting `request_json/4` for HTTPS `POST`/`PUT`/`PATCH` through `SERVICERADAR_EGRESS_PROXY`)
  - `elixir/serviceradar_core/lib/serviceradar/observability/{stateful_alert_rule,event_rule,zen_rule}.ex` and `elixir/web-ng/lib/serviceradar_web_ng/dashboards/` (`pack_id`, `pack_version`, `managed`, `template_fingerprint`, `parameter_overrides` fields and pack export/reconcile hooks)
  - `elixir/serviceradar_core/lib/serviceradar/credentials/credential_usage.ex` and `elixir/serviceradar_core/lib/serviceradar/identity/rbac/catalog.ex`
  - `elixir/serviceradar_core/priv/solution_packs/storage-and-nvr-health/` (Built-in Pack #1) and Ash migrations under `elixir/serviceradar_core/priv/repo/migrations/`
  - `elixir/web-ng/lib/serviceradar_web_ng_web/live/catalog_live/` and `controllers/api/solution_pack_controller.ex`
  - `js/cli/src/pack/` (`validate`, `build`, `sign`, `index`), `js/cli/package.json` (`serviceradar` bin alias), and cross-language signature conformance fixtures
