## ADDED Requirements

### Requirement: Single vendored crate universe

Bazel SHALL resolve the workspace's Rust third-party dependencies from one locally
vendored crate universe generated by a single manifest-based `crates_vendor` rule
(`manifests = ["//:Cargo.toml"]`, `cargo_lockfile = "//:Cargo.lock"`) rooted at
`//third_party/crates`. The build MUST NOT define a second, disjoint copy of any crate
via a curated `packages`-only universe that coexists with the manifest universe.

#### Scenario: Manifest universe reproduces the resolved graph

- **WHEN** `bazel run //third_party:crates_vendor` is executed
- **THEN** the vendored set contains exactly the crates and versions resolved by
  `//:Cargo.lock` (plus declared optional extras)
- **AND** each third-party crate is present exactly once across the universe.

#### Scenario: No coexisting duplicate universe

- **WHEN** the build graph is analyzed
- **THEN** no Rust target resolves a crate from both `//third_party/crates` and a
  separate `packages`-only vendor set
- **AND** a proto-generated type (e.g. `serviceradar_metric_proto::pb::MetricBatch`)
  and its consumers all bind the same single `prost` crate.

### Requirement: Macro-compatible per-crate migration

The vendored universe SHALL expose the same `all_crate_deps`, `crate_deps`, and
`aliases` macros as the previous `@rust_crates` universe, keyed by the same package
names, so that migrating a BUILD file is a load-path change only, with no change to
its dependency lists.

#### Scenario: BUILD change is a load swap

- **WHEN** a `rust/*/BUILD.bazel` file is migrated
- **THEN** its only change is `load("@rust_crates//:defs.bzl", …)` →
  `load("//third_party/crates:defs.bzl", …)`
- **AND** its `all_crate_deps(...)` / `crate_deps([...])` calls are unchanged
- **AND** the target builds against the vendored crates.

### Requirement: Atomic cutover without mixed sourcing

The migration SHALL land all BUILD-file cutovers and the `@rust_crates` extension
removal together, so that once complete no target references `@rust_crates`, and a
target MUST NOT link two copies of the same crate (vendored and `@rust_crates`) that
meet through shared Rust types.

#### Scenario: Whole tree references one source after cutover

- **WHEN** the cutover is complete
- **THEN** `grep -r '@rust_crates' rust/ MODULE.bazel` returns no matches
- **AND** `bazel build //rust/...` and `bazel test //rust/...` pass.

#### Scenario: Shared-type consumers stay consistent mid-migration

- **WHEN** a crate whose public API exposes prost/tonic types is migrated
- **THEN** every crate that consumes those types through a Rust interface is migrated
  in the same cutover, so the shared crate resolves to one rlib.

### Requirement: Annotation carry-over and local-mode patch application

The vendor rule SHALL carry the crate annotations through its `annotations` attribute:
`cri-api` protoc build inputs, and the `openssl-sys`/`openssl-src` build wiring
(perl-wrapper, source filegroups, `RULES_RUST_OPENSSL_SRC_DIR`). Because crates_vendor
local mode does NOT apply annotation `patches` to the on-disk vendored source,
`scripts/vendor.sh` SHALL re-apply the `openssl-src` source patch (idempotently) after
`bazel run //third_party:crates_vendor`.

#### Scenario: cri-api receives protoc

- **WHEN** `cri-api`'s build script runs under the vendored universe
- **THEN** `PROTOC` points at `@bazel_tools//tools/proto:protoc` and codegen succeeds.

#### Scenario: openssl-src patch survives re-vendoring

- **WHEN** `scripts/vendor.sh` runs (vendor + post-patch)
- **THEN** `third_party/crates/openssl-src-*/src/lib.rs` contains the `source_dir()` /
  `-no-canonical-prefixes` fixes
- **AND** re-running the script does not double-apply the patch.

### Requirement: OpenSSL is portable — rustls where practical, vendored where not

The build SHALL NOT depend on host OpenSSL library paths. flowgger's TLS SHALL use
rustls (removing the `openssl` 0.10 crate), and the remaining libpq `openssl-sys` (via
`pq-sys` bundled) SHALL build a from-source (vendored) OpenSSL under Bazel — the system-
OpenSSL `.bazelrc` overrides are removed.

#### Scenario: vendored openssl-sys builds from source under Bazel

- **WHEN** `//third_party/crates/openssl-sys-0.9.116:openssl_sys` is built
- **THEN** it configures and compiles OpenSSL from the vendored `openssl-src` source
- **AND** does not read `OPENSSL_LIB_DIR`/`OPENSSL_DIR` from the host.

#### Scenario: flowgger builds without OpenSSL

- **WHEN** `//rust/flowgger:flowgger_lib` is built with the `tls` feature
- **THEN** it links rustls (`ring`) for syslog TLS
- **AND** neither `openssl` (0.10) nor `openssl-src` is in flowgger's dependency graph.

### Requirement: Referenced extras kept, vestigial extras dropped, no repin

The vendored universe SHALL resolve from the committed lock with no `--repin`. The
`ironrdp-core`/`ironrdp-pdu` `crates.spec` extras SHALL be kept as `packages` (they are
referenced by `rust/rdp-adapter` via `@rust_crates//:ironrdp-*`, need top-level aliases,
and are already in `//:Cargo.lock`). `libzetta` SHALL be dropped (referenced by no
`Cargo.toml`, `Cargo.lock`, or BUILD target).

#### Scenario: ironrdp aliases exist; libzetta is gone

- **WHEN** the vendored universe is generated
- **THEN** `//third_party/crates:ironrdp-core` and `//third_party/crates:ironrdp-pdu`
  resolve (for `rust/rdp-adapter`'s `ironrdp-backend` feature)
- **AND** no `libzetta` alias or target is generated
- **AND** the RDP connector targets still resolve `ironrdp-*` from `@rdp_connector_crates`.

#### Scenario: Vendor resolves from the committed lock unchanged

- **WHEN** `bazel run //third_party:crates_vendor` runs without `--repin`
- **THEN** the vendored set matches `//:Cargo.lock` with no version drift.

### Requirement: Cargo splicing eliminated

After cutover, the `crates.from_cargo` extension SHALL be removed from `MODULE.bazel`
so that Rust builds no longer run the `Splicing Cargo workspace for rust_crates` step.

#### Scenario: No splice on a clean build

- **WHEN** a clean `bazel build //rust/...` is run after the extension is removed
- **THEN** no `Splicing Cargo workspace for rust_crates` action executes.

### Requirement: Independent RDP connector universe unaffected

The migration SHALL NOT merge or alter the separate `rdp_connector_crates` extension,
which vendors `//rust/rdp-connector-probe` from its own `Cargo.lock`.

#### Scenario: RDP connector build is unchanged

- **WHEN** the main universe is migrated to local vendoring
- **THEN** `rdp_connector_crates` remains a distinct extension
- **AND** `//rust/rdp-connector-probe` continues to build from its own lockfile.
