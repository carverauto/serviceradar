# Immutable archive upload intent

`Camera.ArchiveUploads.prepare/3` accepts a current upload handle and either
`:init` or `:media`. It locks the retained recording block through
`RecordingBlocks.with_current_upload/3` and derives the object key, byte length
and SHA-256 from its frozen descriptor. The already bound destination supplies
the destination UUID and digest; callers cannot select another URL, key or hash.
The original upload deadline is rechecked with fresh database time before commit.

One immutable `Camera.ArchiveUploadIntent` exists per block and role. Concurrent
exact retries return the same retained row. A different retained identity fails
without replacing it. Recorder release and upload lease replacement do not change
that identity. Restrictive references keep the block and destination while an
intent exists. There is no update or delete action. The resource's create action
is a trusted persistence primitive; application callers use the coordinator for
fencing and derivation. Internal actor policy does not replace that contract.

Preparation rejects an ambient database transaction so a successful return names
a committed intent. This is still not permission to send a request. Preparation
itself performs no provider I/O or availability transition.
The separate [publication contract](archive-publication.md) owns proof-derived
manifest preparation and fenced index publication. The
[dispatch checkpoint](upload-dispatch.md)
adds bounded marker and response observations beside this immutable identity.
Provider qualification and current credential/policy checks remain separate.

`RecordingDescriptor.object_key/2` owns the key spelling used by both preparation
and `RecordingManifest`. Existing independently calculated manifest hashes and
keys remain unchanged. Init bytes are bounded at 1 MiB and media at 512 MiB by the descriptor;
the new table also constrains role, size and digest shape. These are format bounds,
not deployment capacity or admission targets.

The new guarded database owner tests derived identity and exact retries across
lease replacement, denied and expired preparation, concurrent retries, restrictive
block deletion, ambient-transaction rejection and conflicting retained content.
Each test deletes its own intents, block and binding and rechecks absence before
shared fixture cleanup. Ordinary RBE compilation/selection is not execution of
these database cases. Migration and snapshot are generated by
`//elixir/serviceradar_core:update_camera_upload_intent_schema`.
