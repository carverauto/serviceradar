# Design — fix-anomaly-spike-flapping-and-duplication

## Context

`restore-anomaly-alerting-and-surfacing` made the anomaly pipeline visible again; what surfaced is a set of detection-quality defects in the spike (rolling robust z) path and in seasonal baseline delivery. Live forensics on demo (2026-07-16, addon v0.2.0) plus a reproduction against the shipping `anomaly-backtest` binary established the following verified failure chain for the headline symptom (a confirmed "breach" on visually flat interface traffic, e.g. tonka01 `ifOutUcastPkts` ifIndex 49, score 4.72 at 04:27 UTC on 27–75 pkt/s traffic):

1. **Rolling baseline lock-in.** `include_in_baseline = !breached` (rust/anomaly-core/src/detector.rs:305-312) permanently withholds breaching samples, and window eviction happens only inside `admit_clean_sample` (detector.rs:194-208), so a series that rises off its night level starves the window: the baseline freezes (observed `mean=15.75, stddev=7.24, sample_count=300` pinned for hours while true median was 21–80), and ordinary daytime samples read z≥3 forever. Reproduced: a benign step 15→55 pkt/s keeps the detector in `anomalous` with a frozen window for 38+ hours. The code comment at the withhold site says false positives are prevented by dispersion floors and saturation gates — but `counter_series_profile()` (rust/anomaly-addon/src/metrics_classify.rs:163-169) ships interface counters with `min_std_floor: 0.0, min_cv: 0.0, saturation_gate: None`; only the built-in near-zero guard applies (max of scale, 5% of center, abs 1.0 near zero), which is inert at these levels (floor ≈0.79 vs clean-sample scale 7.24 — the exact 4.72 score proves it never engaged).
2. **No adoption path for spikes.** Drift/CUSUM has `drift_adopt_after_samples` re-anchoring (engine/mod.rs:425-429), but drift is `DeseasonalizedOnly` for interface counters and is inert without a delivered baseline. The rolling path has no adoption analogue.
3. **Seasonal delivery is structurally broken end-to-end** (so drift can never rescue the spike path):
   - The SRQL `stats:profile_hour_of_week` feed the `EdgeBaselineProducer` reuses returns one row per series (latest bucket only), so delivered "hour-of-week baselines" carry ≤1 of 168 buckets — observed on demo as single-bucket `{dow:4, hod:3, sample_count:2, scale:0.0}` payloads. A baseline bucket almost never matches the scoring hour.
   - Interface baselines are scoped by `partition` but matched against `AddonAssignment.agent_uid` — they can never attach to any assignment. Observed: 0 interface baseline keys across all 15 agents.
   - The edge trusts buckets only at `sample_count >= 4` (`DEFAULT_SEASONAL_MIN_BUCKET_SAMPLES`, engine/seasonal_profile.rs:17) while core delivers buckets with `sample_count: 2` — even delivered host buckets are silently untrusted.
   - The addon's seasonal signal has no config toggle; "signal disabled" is emitted both when nothing was configured and when no bucket matches, so forensics cannot distinguish the two.
4. **Flap-merge exists only for drift.** The spike lifecycle destroys episode identity at clear (`reset_active_episode`, engine/episode.rs:~120); `episode_uid = uuid(finding_uid, episode_started_at)` (verdict.rs:550-554) so every re-open mints a new episode. Core's `reopen_count` increments only on a same-`episode_uid` cleared→open conflict (anomaly_episode_registry.ex ON CONFLICT), which is structurally unreachable for spikes. Spikes also never emit severity-escalation `update` transitions (`AnomalyTransition::Update` is produced only inside the drift lifecycle), so the documented "spike findings follow the same episode lifecycle as drift" is unimplemented in both respects. Observed: 85 episodes/48h on one series, `reopen_count=0` everywhere, zero `flap_merged` clears.
5. **Duplicate producers.** Episode upsert conflicts on `episode_uid` alone; edge episode identity has no agent component but each agent's independent state opens at different nanoseconds, so two agents polling the same target lawfully persist two parallel episode streams per canonical series. On demo, the "Default SNMP" profile pins `agent_ids={agent-dusk01, agent-sr-test-pve04}` with `target_query=in:devices` — every target is double-polled (15/15 targets). There is no target-ownership concept in SNMP config compilation and no core-side series-level episode dedupe. (Core does re-derive a shared `finding_uid` and the seeded alert rule groups by device+series, so alerting partially collapses the pair; episode rows and volume do not.)
6. **Severity and alerting inflate the noise.** With zero floors, a 15→424 pkt/s blip scores z≈56, pins the 50.0 cap, and passes the relative-only practical-significance gate (≥30% of a tiny center) to High. The seeded anomaly alert rule fires on any confirmed open (`threshold: 1`, no `severity_number_min`, `severity_from: source`) — 1,180 critical "Anomaly Finding" alerts in 48h on demo. Two aggravators: the per-class `severity_cap`/`severity_bands` keys that Settings projects to the edge are parsed by the addon config but read by nothing (`MetricClassOverride` drops them, config.rs:565-578) — the operator severity-override channel is dead config; and the core ingest 12/hr per-finding rate guard exempts clears, so clear churn always persists.
7. **Harness coverage gap.** The existing diurnal harness scenarios mute the rolling signal (n_sigma set to 100/1e12) and assert only about drift rows; the proof-corpus generator truth-labels recurring diurnal alerts as correct. Nothing asserts bounded spike episodes on a diurnal series at production thresholds.

## Goals / Non-Goals

- Goals:
  - A diurnal series with no delivered baseline produces a bounded number of spike episodes per day at production defaults, and a permanent level shift is adopted, not alarmed forever.
  - Flapping is bounded by episode identity reuse (reopen/flap-merge) on the spike path, mirroring drift.
  - Two producers for one canonical series cannot double episode volume.
  - Seasonal baselines actually work end-to-end (full bucket coverage, correct scoping, aligned trust gates) so `deseasonalized_only` drift stops being structurally inert.
  - Near-idle interfaces cannot mint High/critical findings from operationally trivial changes.
- Non-Goals:
  - No changes to the scope owned by `restore-anomaly-alerting-and-surfacing` (crons, rule seeding/reconciliation, Horde shard placement, capacity opt-ins, silence tripwires).
  - No new detector families; CUSUM/drift semantics stay as specified.
  - No automated remediation.
  - Polling-topology redesign (target ownership / rendezvous hashing in SNMPCompiler) is out of scope; we take the ingest-side fold plus config-hygiene surfacing instead.

## Decisions

- **Decision 1 — bounded withholding via winsorized admission + spike adoption (combined).**
  - *Winsorized admission* (rust/anomaly-core): on the breach arm, admit the sample clamped to `center ± n_sigma × scale` instead of dropping it. The window keeps aging on every sample; the median migrates toward a persistent new level in ~window/2 samples; genuine spikes stay damped and cannot inflate the MAD, preserving the anti-self-masking property.
  - *Spike adoption* (rust/anomaly-addon): mirror `drift_adopt_after_samples` — when a series has been continuously anomalous for `spike_adopt_after_samples` (default aligned with drift, 600 samples) without severity escalation and not saturation-gated, rebuild the rolling window from a small raw ring of recent samples (admitted and withheld), clear the episode with reason `adopted`, and resume.
  - Why both: winsorization fixes the gradual-ramp bias and starvation; adoption bounds the worst case (large step shifts where even winsorized admission converges slowly) and gives an explicit, observable lifecycle event. Alternatives considered: admission hysteresis band (only moves the lock-in boundary), count-based window aging to `insufficient_baseline` (trades a wrong baseline for no baseline and silently disables detection).
  - Withheld/clamped samples are counted per series and surfaced in telemetry (parallel to `drift_inactive_no_baseline`).
- **Decision 2 — spike reopen/flap-merge parity with drift (edge-first, core backstop).** Add `spike_last_cleared_at`, `spike_last_episode_started_at`, `spike_reopen_count` to `SeriesState`; on open within `reopen_cooldown_secs` of the last clear, reuse the previous `episode_started_at` (hence the same `episode_uid`), increment reopen count, emit transition `update`/reason `flapping`; rewrite the eventual clear to `flap_merged` when `reopen_count > 0`; persist in checkpoints; include `reopen_count` in the spike payload. Because the `episode_uid` is reused, core's existing ON CONFLICT reopen path works with zero core changes. Core backstop: on an incoming open whose `finding_uid` has an episode cleared within the flap window, fold into that row (aliasing the new `episode_uid`) so stale producers are also bounded.
- **Decision 3 — duplicate-producer folding at ingest, not polling exclusivity.** In `AnomalyEpisodeRegistry`, fold an incoming open whose canonical `series_key` already has an open episode into that row (update `last_seen`, peaks, occurrence; alias the incoming `episode_uid` for subsequent update/clear resolution), and count multi-producer series in telemetry. Surface a config-hygiene warning listing doubly-polled SNMP targets. Rationale (network-agnostic identity feedback): behavior-level folding works for any topology; pinning polling to one agent is a demo runbook item, not a product invariant.
- **Decision 4 — fix seasonal delivery shape, scoping, and trust gates.**
  - Full-profile feed: give `EdgeBaselineProducer` an SRQL variant returning every populated `(dow, hod)` bucket per series (the existing latest-bucket shape stays for central disposition).
  - Bucket/coverage gates: do not deliver buckets below a minimum per-bucket sample count, nor baselines below a minimum bucket-coverage fraction; keep such series in `drift_inactive_no_baseline`.
  - Scoping: resolve which agents actually poll a device (not `partition == agent_uid`) and write scoped interface baselines to every enabled anomaly assignment of every such agent.
  - Trust alignment: a delivered bucket the edge would reject (`min_bucket_samples`) must not be delivered; the gate value ships in the delivered payload so edge and core cannot drift apart silently.
  - Diagnosability: the addon emits distinct seasonal reasons for "no baselines configured" vs "no bucket for this hour" vs "bucket below trust threshold".
- **Decision 5 — interface-class floors and absolute significance.** `counter_series_profile()` gets non-zero rolling floors (`min_cv` and a per-family absolute floor, pkt/s vs B/s), and `practical_significance_passes` gains an absolute-effect term for counters: `delta >= max(0.30 × center, abs_effect_floor)`, with `abs_effect_floor` a new `SeriesProfile` field (default preserves current behavior for other classes). When SNMP `ifSpeed`/`ifHighSpeed` is known, the dormant `max_counter_rate_per_second` hook may be wired later as an additional High gate; not required for this change.
  - Interim demo mitigation (no release needed): project `metric_classes.interface.min_cv`/`min_std_floor` via the existing Settings → `AnomalyAddonConfigProjector` channel.
- **Decision 6 — alert-rule severity floor stays out of scope but documented.** The seeded rule pages on any confirmed open; with Decisions 1–5 the open volume collapses. If paging should be High-only, the one-line `severity_number_min` change to the seeded rule template belongs to the alerting owner; noted in ops runbook, not spec-mandated here.

## Risks / Trade-offs

- **Winsorized admission changes every class's baseline dynamics**, not just interfaces → guard with the scorecard CI floors (spike precision, drift FPR) and the new diurnal scenario; the clamp bound is the alert threshold, so clean-regime behavior is unchanged by construction.
- **Adoption can absorb a real sustained incident after the horizon** (e.g. an interface saturated by exfiltration for >10h reads "adopted") → adoption emits an explicit `adopted` clear (auditable), is blocked inside saturation bands, and the horizon is per-class configurable; capacity/threshold paths still cover sustained-high conditions.
- **Episode-uid aliasing in core fold paths** risks mis-attributing transitions if two genuinely distinct conditions overlap on one series → fold key is the canonical `finding_uid` (one series, one condition, per spec), which is already the product's identity contract.
- **Seasonal full-profile payloads are larger** (up to 168 buckets/series) → existing per-agent payload caps and top-K governance apply; compact array wire shape already exists.
- **Behavioral shift in severity distribution** (BREAKING, intended): dashboards keyed on High interface anomalies will show fewer findings.

## Migration Plan

1. Land edge changes behind the addon version bump (0.2.0 → 0.3.0); managed-config knobs default to current behavior where feasible (`abs_effect_floor=0` for non-interface classes).
2. Core ingest fold + baseline producer changes ship in the same release; both are backward-compatible with 0.2.0 producers (core backstop handles old addons).
3. Demo rollout order: config-only mitigation first (interface floors via projector; unpin one of the two SNMP agents), then release, then soak against the documented gates (<1,000 rows/day fleet-wide, ≤20 rows/series/day, Critical share <5%, alert volume sanity).
4. Rollback: addon package retarget to 0.2.0; core fold paths are additive and keyed off payload fields present only in 0.3.0, plus env kill switches for the core-side fold backstop.

## Open Questions

- Default `spike_adopt_after_samples`: mirror drift's 600 samples (10h at 1/min) or shorter (120–300) for counter classes? Proposal: per-class default, interface counters 300.
- Should the multi-producer fold prefer the earliest-open producer's episode or the most-recently-heartbeating one when reconciling contradictory states (one open, one clear)? Proposal: episode stays open while any producer holds it open; clears require all producers clean or stale timeout.
- Minimum bucket-coverage fraction for delivering a seasonal baseline: propose 60% of the 168 buckets, aligned with a 3-week minimum history gate.
