# Change: Fix anomaly spike-path flapping, baseline lock-in, and duplicate-producer episode churn

## Why

Now that `restore-anomaly-alerting-and-surfacing` has made the anomaly pipeline visible again (episodes on, alerts firing, device panels populated), the surviving detection-quality defects are paging operators with confirmed-but-meaningless findings. Live demo forensics (2026-07-16, addon v0.2.0, single enabled profile, projector and baseline producer running):

- **A confirmed breach on operationally flat traffic.** Device tonka01 (`sr:129bcb1f`, SNMP target 192.168.10.1) opened `breach confirmed after 5/5 consecutive anomalous slots` on `ifOutUcastPkts` ifIndex 49 at 04:27 UTC with score 4.72 while real traffic sat at 27–75 pkt/s — visually flat. The detector's rolling signal believed `mean=15.75, stddev=7.24` while the true trailing-window median was 21 pkt/s with normal excursions to 93. Root cause: `include_in_baseline = !breached` (rust/anomaly-core/src/detector.rs:312) permanently withholds every breaching sample, so once a diurnal series rises off its night level the baseline can never re-learn — every ordinary sample z≥3 is withheld, the center stays frozen, and the series flaps open/clear forever. The code comment at that exact site says benign-value false positives are prevented by "the std/CV floor (fix #2) and the gauge saturation gate (fix #3)" — but `counter_series_profile()` (rust/anomaly-addon/src/metrics_classify.rs:163) ships interface counters with `min_std_floor: 0.0, min_cv: 0.0, saturation_gate: None`. The one metric class that is both diurnal and bursty has none of the protections the withhold design depends on.
- **No adoption escape for the spike path.** Drift/CUSUM has `drift_adopt_after_samples` re-anchoring, but drift is `deseasonalized_only` for interface counters and zero interface baselines have been delivered fleet-wide (all 15 agents carry 24 host-CPU keys, 0 interface keys; the interface hourly aggregate only started accumulating 2026-07-09). The rolling spike path — the only active detector on these series — has no adoption path at all: bounded silence for drift became unbounded flapping for spikes.
- **Flapping mints unbounded episodes.** One series (`ifOutOctets` ifIndex 4) opened 85 episodes in 48h; the fleet produced 2,755 episodes/48h and 2.1–2.6k anomaly OCSF rows/day — violating the documented soak gates (<1,000 rows/day fleet-wide, ≤20 rows/series/day). `reopen_count` is 0 on every row and no `flap_merged` clears exist: every re-open after a clear mints a fresh `episode_uid` instead of reopening the finding's episode.
- **Duplicate producers double everything.** The demo "Default SNMP" profile assigns `agent_ids={agent-dusk01, agent-sr-test-pve04}` with `target_query=in:devices`, so both agents poll all 15 SNMP targets. Each addon keeps independent rolling state and emits overlapping, phase-shifted episodes for the same canonical series (verified interleaved open/clear streams for `ifOutUcastPkts` ifIndex 49). Core ingest folds by edge `episode_uid`, so both streams persist; the same physical condition double-reports and can even disagree (one producer open 8.5h while the other flaps).
- **Near-idle interfaces pin the score cap and page as critical.** With no dispersion floors, blips like 15→424 pkt/s score z≈56, clip to the 50.0 stored cap, and land High severity via a purely relative practical-significance gate (≥30% of a tiny center). The seeded alert rule (`severity_from: source`, threshold 1) then minted 1,180 critical "Anomaly Finding" alerts in 48h.
- **Seasonal baseline delivery is structurally broken end-to-end**, so drift can never rescue the spike path. (a) The SRQL `stats:profile_hour_of_week` feed that `EdgeBaselineProducer` reuses returns only the latest bucket per series, so every delivered "hour-of-week baseline" carries ≤1 of 168 buckets (observed on demo: single-bucket `{dow:4, hod:3, sample_count:2, scale:0.0}` payloads) and almost never matches the scoring hour. (b) Interface baselines are scoped by `partition` but matched against `AddonAssignment.agent_uid`, so they can never attach to any assignment — observed as 0 interface baseline keys on all 15 agents. (c) The edge trusts buckets only at `sample_count ≥ 4` (`DEFAULT_SEASONAL_MIN_BUCKET_SAMPLES`) while core delivers `sample_count: 2` buckets, so even delivered host buckets are silently untrusted. (d) The addon emits the same "signal disabled" reason whether baselines were never configured or just missed the current hour, so this was invisible in payload forensics.
- **Harness gap.** No proof-harness scenario runs the rolling spike detector against a diurnal series without a delivered baseline. The existing quiet-interface scenario (rust/anomaly-addon/src/tests/engine.rs:2089) bounds scores and episode count for a burst, but nothing asserts bounded spike episodes across a day/night cycle — exactly the shape that shipped broken.

## What Changes

- **Spike-path baseline adoption (rust/anomaly-core, rust/anomaly-addon)**: bound the withhold-from-baseline mechanism. When a series has been continuously breaching (or persistently flapping against a frozen baseline) for a configurable adoption horizon and the new level is stable and non-saturated, re-anchor the rolling baseline to the current level and clear the episode with reason `adopted` — mirroring drift adoption semantics. A real sustained surge still reads anomalous for its full confirm-and-hold duration; it just cannot read anomalous forever.
- **Interface-class dispersion floors and absolute significance (rust/anomaly-addon)**: give `counter_series_profile()` non-zero `min_cv` (and an absolute rate floor derived per series, e.g. from observed peak or ifSpeed when known), and add an absolute practical-significance gate for interface counter rates so a few-hundred-pkt/s blip on a near-idle port cannot reach High/critical purely on relative statistics. **BREAKING**: interface spike severity distribution shifts down; scores no longer pin at the cap for quiet-port blips.
- **Flap-bounded episode identity (rust/anomaly-addon + core ingest)**: a re-open of the same finding within the reopen/flap window SHALL reopen the prior episode (incrementing `reopen_count`, `flap_merged` accounting) instead of minting a new `episode_uid`; core ingest additionally folds re-opens that arrive within the flap window of a clear for the same finding UID, bounding episodes/series/day even against stale producers.
- **Duplicate-producer folding (core ingest)**: fold episode transitions from multiple producers for the same canonical series into one episode stream (deterministic identity from finding UID, not edge episode UID alone), count multi-producer series in telemetry, and surface a config-hygiene warning when more than one agent polls the same SNMP target with the same profile.
- **Seasonal baseline delivery correctness (core-elx EdgeBaselineProducer + rust/srql)**: deliver full hour-of-week profiles (every populated bucket, not the latest-bucket query shape); fix interface baseline scoping to target every agent that actually polls the device instead of matching `partition` against `agent_uid`; gate delivery on minimum per-bucket sample count (aligned with the edge trust gate) and minimum bucket-coverage fraction, keeping below-gate series in `drift_inactive_no_baseline` bounded silence; give the addon distinct seasonal reasons for "not configured" vs "no bucket this hour" vs "bucket untrusted". Interface baselines become deliverable as the (new, 2026-07-09) interface hourly aggregate accumulates history.
- **Verification**: new proof-harness scenario — diurnal interface series, no delivered baseline, rolling spike path only — asserting bounded episodes/day, bounded scores, and adoption clears; demo soak re-check of the documented gates (<1,000 rows/day fleet, ≤20 rows/series/day, critical share, alert volume).

## Impact

- Affected specs: `anomaly-detection`
- Affected code:
  - `rust/anomaly-core/` (detector.rs withhold/adoption state machine, stats.rs scale floors)
  - `rust/anomaly-addon/` (metrics_classify.rs interface profile, engine episode/reopen state, verdict.rs practical significance)
  - `elixir/serviceradar_core/lib/serviceradar/event_writer/processors/` (episode registry: flap folding, duplicate-producer folding)
  - `elixir/serviceradar_core/lib/serviceradar/observability/seasonal_disposition/` (EdgeBaselineProducer feed shape, scoping, bucket-quality gates)
  - `rust/srql/` (full-profile hour-of-week query variant)
  - `docs/docs/anomaly-engine.md`, `docs/docs/anomaly-detection.md`
- Interaction with in-flight changes: complements `restore-anomaly-alerting-and-surfacing` (which restored surfacing and predicted this residual in its P1 flap-rate finding); does not touch its scope (crons, rules, shards, capacity opt-ins). Extends `overhaul-anomaly-engine-reliability` acceptance gates to the spike path.
- Operations: demo mitigation available immediately via config (raise interface-class `n_sigma`/`confirm_slots` through Settings → projector) and SNMP profile hygiene (stop double-polling all devices with two agents) — neither requires a release.
