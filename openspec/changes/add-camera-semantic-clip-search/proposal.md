# Change: Semantic visual clip search and Rust GPU media workers

## Why

Operators and investigators using continuous NVR recording (`add-nvr-retention-and-timeline-playback`) need open-vocabulary visual search across recorded footage (for example `"person in red dress"` or `"white cargo van near loading dock"`) without manually scrubbing hours of timeline video. At the same time, hardware-accelerated keyframe decoding and neural vision inference must run outside the core BEAM failure domain so GPU saturation, native runtime faults, or worker restarts can never disrupt live camera viewing, continuous NVR capture, or archive uploads (`add-vms-storage-playback-engine/media-workers.md` Stage P3).

## What Changes

- Add a standalone stateless Rust GPU media worker daemon (`rust/media-worker`, binary and OCI image `serviceradar-media-worker`, built hermetically under Bazel for both `linux/amd64` x86_64 NVIDIA nodes and `linux/arm64` Grace/DGX-class GPU nodes), scheduled via opt-in Helm `mediaWorker.*` settings (`nvidia.com/gpu` resource limits, `nodeSelector`, `tolerations`) completely outside the BEAM ERTS cluster.
- Add per-policy opt-in visual indexing (`visual_index_mode: :off | :keyframes`, default `:off` on `ServiceRadar.Camera.CameraRecordingPolicy`) and metadata-only durable NATS JetStream job delivery (`media.jobs.visual_index.v1` pull consumer) backed by a transactional CNPG outbox (`platform.camera_visual_index_jobs`) emitted when sealed, non-quarantined `RecordingCatalogEntry` blocks are registered, alongside a reserved low-latency text-query embedding lane (`media.rpc.visual_text_embed.v1`) so bulk historical backfill never starves interactive operator search.
- Add execution-time scoped media read capabilities (`POST /v1/media/workers/read-grants`) authenticated by a domain-separated `media_worker` workload identity (never human RBAC or static Kubernetes bucket Secrets). Workers receive short-lived fragment read plans for the exact `catalog_entry_id`, reading `init.mp4` and sampled IDR keyframe byte ranges either from a dedicated low-priority analysis read pool on the owning NVR local read listener or directly from S3-compatible object storage via `longshore` (`longshore_s3`) using a short-lived `:reader`-only (`GET`, `HEAD`) `CredentialBrokerGrant` resolved through `ArchiveCredentialResolver` from `platform.network_credential_secrets`, verifying every fetched byte slice against the frozen descriptor SHA-256.
- Add a two-stage keyframe vision pipeline in `serviceradar-media-worker` backed by `ort` (ONNX Runtime with TensorRT and CUDA execution providers and explicit startup capability admission -- no silent unbounded CPU fallback): Stage 1 object/person/vehicle detection (`RT-DETR` / `YOLO` family) crops foreground subject bounding boxes (`person`, `vehicle`, `bicycle`, `animal`, `package`) on sampled IDR keyframes (default 1 keyframe per 2 s CMAF fragment, bounded per block) alongside full-scene keyframes; Stage 2 vision-language encoding (`SigLIP` / `MobileCLIP` family, carrying explicit `model_id`, `model_version`, and `embedding_dim` rather than hard-coding one vector width) embeds subject crops and scene frames and emits structured attributes (class, confidence, normalized `[x1, y1, x2, y2]` box, optional coarse color tags).
- Add idempotent JetStream result ingestion (`media.results.visual_index.v1`) into CNPG `pgvector` Ash projection tables (`platform.camera_visual_frames` and `platform.camera_visual_embeddings` with HNSW cosine indexes per active model dimension), strictly coupled to `platform.camera_recording_catalog` lifecycle: `ON DELETE CASCADE` on row removal, immediate purge trigger when a catalog entry transitions to `quarantined` or reaches terminal copy deletion (`local_state = reclaimed` and `archive_state` in `deleted` or `not_required` while the 90-day catalog tombstone row remains), `RecordingHold` preservation, and strict exclusion of quarantined blocks.
- Add an authorized semantic clip search API (`GET /api/cameras/search`) and LiveView UI (`/cameras` fleet search panel in `CameraLive.Index` and `/cameras/:camera_source_id/recordings` timeline search filter in `CameraLive.Recordings`) enforcing `devices.view` + `devices.cameras.recordings.view` and pre-filtering authorized camera `Source` UUIDs before `pgvector` k-NN execution, writing append-only `RecordingAccessAudit` records (`event_kind: :semantic_search`), and deep-linking hits to `/cameras/:camera_source_id/recordings?mode=timeline&from=...&to=...&seek=...` with non-destructive SVG/canvas player bounding-box overlays.

## Impact

- Affected specs:
  - `camera-semantic-search` (new capability; `ADDED` requirements only)
  - `vms-media-workers` (`ADDED` requirements extending Stage P3 worker admission, scoped `longshore`/NVR fragment grants, and interactive text-embedding capacity without modifying pending unarchived deltas)
- Composes with:
  - [VMS storage, playback and media workers](../add-vms-storage-playback-engine/proposal.md), specifically [media-workers.md](../add-vms-storage-playback-engine/media-workers.md) (Stage P3 searchable derivatives) and [cloud-control-plane.md](../add-vms-storage-playback-engine/cloud-control-plane.md) (`C3. GPU placement and environment isolation`)
  - [Scalable camera recording plane](../add-scalable-camera-recording-plane/proposal.md) (worker pools never consume recorder reservations or live camera sessions)
  - [NVR continuous recording, retention and unified timeline playback](../add-nvr-retention-and-timeline-playback/proposal.md) (`RecordingCatalogEntry`, `RecordingHold`, `RecordingAccessAudit`, `ArchiveCredentialResolver`, `CameraRecordingPolicy`, `StorageEntitlement`, `CameraTimelineController`, `CameraLive.Recordings`)
  - [Longshore object storage](../add-longshore-object-storage/proposal.md) (`longshore_s3` bounded Rust S3 client for ranged fragment `GET`s)
- Boundaries:
  - This proposal is specification-only; no code, migration, or chart change ships in this PR.
  - Worker outputs traverse NATS JetStream first (`media.results.visual_index.v1`); workers never connect to CNPG or StarRocks directly.
  - CNPG stores only bounded, retention-coupled visual search projections (`camera_visual_frames`, `camera_visual_embeddings`); worker operational metrics flow through JetStream and `EventWriter` to the configured telemetry backend, avoiding any raw `vms_ai_events` firehose in CNPG.
  - Membrane `Boombox` (`BoomboxBranchManager` / `BoomboxSidecarManager` in `serviceradar_core_elx`) remains owned by live relay tap workflows; recorded-block visual indexing runs in `serviceradar-media-worker`.
  - Audio speech transcription (`Whisper`), OCR, and PostGIS spatial field-of-view projections remain separate P3 changes.
- Affected code when implemented: `rust/media-worker`, `Cargo.toml`, `MODULE.bazel`, `third_party/crate_mirror`, `elixir/serviceradar_core`, `elixir/serviceradar_nvr`, `elixir/web-ng`, `helm/serviceradar`, docs.
