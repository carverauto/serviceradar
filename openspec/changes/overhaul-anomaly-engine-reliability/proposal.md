# Change: Overhaul the anomaly engine for production reliability (episodes, calibrated severity, deseasonalized drift)

## Why

The anomaly engine floods production with false positives: on the demo cluster it produced **294,598 OCSF events in 7 days (84.6% of ALL event ingest), 65.2% of them Critical**, at ~80k/day and growing. 91.5% of current volume is the CUSUM drift path ("sustained downward/upward drift") firing one Critical per poll cycle, forever, on diurnal interface traffic — the top series re-fires with a **median gap of 0.8 seconds** (5,118 events/24h for one interface). Operators correctly identify the remainder (single-core CPU spikes, drift Criticals at 28% CPU, capacity "runway" on a 6%-avg bursty gauge) as noise they will learn to ignore, which defeats the product.

This is not a tuning problem. Verified root causes (full analysis in `design.md`): the drift detector anchors permanently to its first ~15 minutes of samples and re-alarms indefinitely with no lifecycle; interface counters are structurally excluded from the only silencing mechanism (hour-of-week baselines) despite the repo's own proof harness recording **42–74% false-positive rates for raw CUSUM on seasonal data**; severity maps an *unbounded accumulator* (observed max 6.6×10²³) onto z-score cutpoints so drift is Critical by construction; a `f64::EPSILON` scale floor turns quiet interfaces into astronomical-score Critical generators; ingest persists every report as a new immutable row (the deterministic `finding_uid` is computed then ignored); and the Settings UI config never reaches the edge detector. Six prior OpenSpec changes attacked pieces of this and stalled partially implemented; none was archived, so no anomaly capability spec exists to constrain regressions like the drift detector shipping default-ON.

## What Changes

- **Edge drift detector (rust/anomaly-addon, rust/anomaly-core)**: keep the CUSUM statistic; replace frozen-anchor/reset-and-re-accumulate/emit-per-alarm semantics with per-class `drift_mode` (`off` | `deseasonalized_only` (default) | `always`), latch-and-confirm alarms with a minimum effect size, an open/clear **episode lifecycle** mirroring the existing spike path, adopt-the-new-level re-anchoring, and the same near-zero scale floor the z-path already has. Per-class detector defaults gate which metric families have drift at all; `cpu.frequency_hz` is denylisted; pid/start_time leave the series key. **BREAKING**: the addon no longer emits per-alarm drift findings; `cusum_enabled` is superseded by `drift_mode`, is not part of the 0.2.0 schema/UI surface, and is ignored by the 0.2.0 runtime if stale profile data still carries it.
- **Severity calibration**: bounded evidence scores (never a raw accumulator), per-class bands with practical-significance gates, impact tests for Critical (resource saturation, not mere statistical surprise), edge drift capped at High, per-core CPU series capped at High. **BREAKING**: severity distributions shift downward; alert rules keyed on Critical see far fewer, more meaningful events.
- **Episode semantics end-to-end (core-elx)**: one logical anomaly = one episode. Ingest folds transitions against an episode registry keyed by the existing deterministic `finding_uid` (new `AnomalyEpisode` Ash resource + bounded transition rows in `ocsf_events`), with a producer-version-independent backstop that collapses re-fire storms from stale addons. Payload stored once (~6.3KB → ~2KB/row). Legacy class-1008 fallthrough for anomaly payloads is closed. Only transitions enqueue alert evaluation.
- **Emission governance**: per-series cooldown, per-addon budget with prioritized coalescing into auditable shed rollup records (reusing existing shed machinery), core-side flood tripwire. No silent drops anywhere.
- **Seasonal coverage for interface counters**: hour-of-week baselines keyed `<device_uid>|<metric_name>|<if_index>`, delivered through the existing EdgeBaselineProducer channel with per-agent scoping, top-K interface selection, and hard payload caps. Until a series has a baseline, drift on it is off (bounded silence, never fabricated alarms).
- **Config unification**: project the Settings-UI singleton (`platform.anomaly_detection_configs`) onto the anomaly AddonProfile params via a new reversible projector worker, so operator tuning finally reaches the edge; per-class knobs and kill switches at every layer.
- **Host-aggregate CPU evaluation**: synthesize host-level cpu series at the addon (mean + cores-above-gate) as the Critical-eligible alerting unit; per-core series (32 independent detectors per host today, the only cpu alerting unit that exists) are demoted to High-capped context.
- **Restore the anomaly alert pipeline**: the stateful alert engine has fired **zero anomaly alerts since the 2026-06-30 signals cutover** (19,024 fires before, none across 295k events since), and fired alerts reference `alert_ids` that don't exist in `platform.alerts` — root-cause both, fix, and add a blocking post-deploy alert-liveness check.
- **Capacity forecasting soundness**: restrict runway forecasting to monotone consumable resources by default (63% of current `projected` findings are on bursty near-idle CPU/interface gauges against a 100% ceiling); significance gates (robust slope CI, m-of-n persistence, extrapolation ≤ ~2× observed history, PI-lower-bound ETA); transition-only emission (today: 3,067 verdicts per hourly run, ingest backlogged 2–4 days); fix interface findings attributing to device `default` (97%); honor configured model/threshold (both silently dropped today); fix the UI mislabeling of projected crossing time as "Observed".
- **Interface rate integrity (UI/SRQL — collection is verified healthy)**: 64-bit ifHC polling works end-to-end; the gappy charts are a double-rate-conversion regression (device page: `agg:rate` + `rate_mode: :counter` drops ~50% of buckets; detail page: raw counters labeled B/s) — enforce one conversion site, partition SRQL `agg:rate` deltas per polling series, bound the wrap branch, and add drop-reason telemetry.
- **Findings surface legibility (web-ng)**: decode the v2 hex series key into human-readable fields in finding modals; clamp/explain out-of-window metric-context markers; fix the `@chart_pad` crash that has always prevented detection-window bands from rendering; fix clipped y-axis tick labels and invisible single-point segments; debounce the events page's per-broadcast full refresh.
- **Verification**: five new proof-harness scenarios (diurnal sinusoid, quiet interface, regime change, restart storm, re-fire cadence) wired as CI gates, plus command-level live SLO checks on demo (< 1k anomaly events/day fleet-wide, Critical share < 5%, no series > 20 rows/day, zero scores > 50).
- **OpenSpec debt**: this change supersedes/absorbs the six stalled anomaly changes, archives the completed generations, and creates the first `anomaly-detection` capability baseline spec.
