# Change: Harden Pod DNS Configuration and Cluster Resolver Path (#6518 Follow-Up)

## Why
Every ServiceRadar pod previously inherited Kubernetes's default `ClusterFirst` `/etc/resolv.conf` (`options ndots:5` with glibc's 5-second initial UDP retry timer and dual-stack `A`/`AAAA` lookups sharing one UDP socket). Under that posture:
1. Any intra-cluster hostname with fewer than 5 dots (such as bare `<service>` or 2-dot `<service>.<namespace>.svc`) triggers search-domain walks that amplify DNS traffic with avoidable `NXDOMAIN` lookups before reaching the authoritative name, or transiently return `:nxdomain` / `SERVFAIL` when one UDP search-path exchange drops.
2. A single lost UDP DNS packet stalls glibc's stub resolver for 5,000 ms before its first retry, consuming the entire 5-second TCP/HTTP connect budget of Elixir (`Mint`/`Req`), Go (`net.Dialer`), and Rust (`reqwest`/`tonic`) clients without raising per-caller timeouts.
3. On cluster nodes using the Linux kernel default `net.core.rmem_default = 212992` (208 KiB), amplified concurrent dual-stack UDP `:53` bursts overflow CoreDNS pod socket receive buffers (`Udp: RcvbufErrors` inside the CoreDNS pod network namespace, invisible to host-namespace `node_netstat_Udp_RcvbufErrors`).

## What Changes
- **Fixed chart pod `dnsConfig` defaults (no Helm-only toggle)**: Emit a shared `serviceradar.podDnsConfig` helper (`ndots: "2"`, `timeout: "2"`, `attempts: "2"`, `single-request-reopen`) unconditionally across all 36 pod-bearing manifests in `helm/serviceradar` (19 Deployments including `dev/faker` and `files/serviceradar-tools.yaml`, 2 StatefulSets, and 15 Jobs) and `helm/serviceradar-k8s-edge` (`deployment.yaml`), plus all 5 workload templates in the bundled `dgraph` subchart (`alpha` and `zero` StatefulSets, `ratel` Deployment, and `cronjob-full` / `cronjob-inc` CronJobs), whose upstream `dgraph-24.1.4` templates expose no `dnsConfig` value, by vendoring that pinned subchart unpacked under `helm/serviceradar/charts/dgraph` and emitting the same fixed block in its pod templates. Per-caller client connect timeouts remain unchanged.
- **Explicit intra-cluster FQDNs and TLS SAN parity**: Default intra-cluster Service addresses rendered by `helm/serviceradar` (including hook Job API server URLs and cross-namespace service references such as StarRocks FE HTTP/MySQL endpoints) to explicit 4-dot FQDNs built from the Kubernetes Service name (`<service-name>.<namespace>.svc.cluster.local`, e.g. `serviceradar-core.<namespace>.svc.cluster.local`), extend `helm/serviceradar/files/generate-certs.sh` so the leaf certificate of every TLS-serving chart Service carries that exact name as `DNS:<service-name>.<namespace>.svc.cluster.local` (`serviceradar-web-ng`, `serviceradar-rperf-client`, `serviceradar-flow-collector`, `serviceradar-bmp-collector`, `serviceradar-trivy-sidecar`, and `serviceradar-k8s-inventory`, matching the existing `serviceradar-nats`, `serviceradar-core`, `serviceradar-datasvc`, `serviceradar-agent`, `serviceradar-agent-gateway`, `serviceradar-log-collector`, and `serviceradar-trapd` SANs), and bump `certs.runtimeLayoutVersion` from `"5"` to `"6"`.
- **Cluster host UDP receive-buffer sizing (node sysctl companion)**: Pair the chart change with cluster host (`init_net`) `net.core.rmem_default >= 8388608` (8 MiB) and `net.core.rmem_max >= 16777216` (16 MiB) on every Kubernetes node followed by rolling CoreDNS pods so newly opened CoreDNS UDP `:53` sockets inherit an 8 MiB receive buffer rather than the 208 KiB default. Deploying `NodeLocal DNSCache` (`169.254.20.10` / `force_tcp` DaemonSet) or modifying per-node kubelet `clusterDNS` flags is explicitly out of scope (Non-Goal).

## Impact
- Affected specs: `cluster-dns-resilience` (added)
- Affected code:
  - `helm/serviceradar/templates/_helpers.tpl`, `helm/serviceradar/values.yaml`, `helm/serviceradar/values-demo.yaml`, `helm/serviceradar/files/serviceradar-config.yaml`, `helm/serviceradar/files/serviceradar-tools.yaml`, and all 36 pod-bearing templates/files in `helm/serviceradar`
  - Vendored `dgraph` subchart (replacing `helm/serviceradar/charts/dgraph-24.1.4.tgz` with unpacked `helm/serviceradar/charts/dgraph`) workload templates
  - `helm/serviceradar/files/generate-certs.sh`
  - `helm/serviceradar-k8s-edge/templates/_helpers.tpl` and `deployment.yaml`
  - Cluster node host `sysctl` configuration (`net.core.rmem_default` and `net.core.rmem_max`)
