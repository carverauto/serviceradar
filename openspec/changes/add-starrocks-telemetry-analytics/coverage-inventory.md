Unknown consumers block cutover. CNPG remains authoritative for inventory, auth, config, credentials, Oban, AGE, and current alert state. Helm `analytics.starrocks.enabled` warehouses flows/metrics/logs/events (off by default). `flowCollector.enabled` is independent and does not require StarRocks. Off StarRocks means remaining telemetry on CNPG hypertables. Default chart `cutoverDatasets` stays empty so serving remains CNPG; the demo overlay `helm/serviceradar/values-demo.yaml` cuts over `flows` and `metrics` only.

Rollback: serving follows `Readers.mode_for/1`. Removing `metrics`, `logs` or `events` from Helm `cutoverDatasets` returns that dataset to CNPG, which keeps receiving every write; the change takes effect when the checksum annotation rolls web-ng and core. Removing `flows` does not fall back: flows are warehouse-only, so every flow read is refused until it is listed again. EventWriter stays CNPG-first until a separate 6.7 writer cleanup. Only the demo deployment is cut over, for `flows` and `metrics`; the default chart values cut nothing over.

CNPG JDBC catalog (`cnpg_platform`) is specified for query-time joins of StarRocks facts to allowlisted `platform` current-state tables, first for flow attribution and enrichment (`flow_process_attribution_current`, `prefix_tags`, `ocsf_devices`). Helm `catalog.enabled` is false. It is not a telemetry serving path.
