# Change: Add Endpoint SBOM Inventory

## Why
Operators need first-party endpoint software visibility to answer incident questions such as "which assets have nginx installed?" without relying on demo fixtures, ad hoc SSH checks, or external endpoint tools. ServiceRadar currently has bounded Bumblebee exposure findings and process/flow attribution, but it does not collect full installed package inventory or endpoint SBOM artifacts.

The design must be the scale-correct architecture from the start, not a small-fleet design we upgrade later. Uploading a full package/SBOM snapshot from every endpoint on every scan, and rewriting every package row on every scan, would turn routine inventory collection into hundreds of millions of row operations per day at 100k+ hosts. Endpoint software inventory keeps detailed state close to the endpoint, persists central state only when it changes, splits durable storage into queryable current-state and compressed time-series history, and answers fleet questions from incremental aggregates and live edge queries.

The value is automation, not a picture. Inventory plus CVE coordinate-matching produces vulnerability findings that create events and alerts, enrich device/service risk state, and feed the DeepCausality causal engine to predict failure and manage risk. The topology/god_view graph is one optional renderer of verdicts — not the primary consumer, and not the substrate inventory is modeled for.

## What Changes
- Add an opt-in, policy-controlled endpoint software inventory collector for managed agents (Linux dpkg/apt, rpm/dnf/yum, apk first), delivered as a signed native add-on.
- Compute deterministic, versioned `package_set_hash` and `artifact_hash` on the endpoint and gate all uploads on hash change: unchanged scans send only a lightweight status/hash heartbeat; the full CycloneDX artifact and normalized rows upload only when the hash changes or a guarded force-refresh occurs.
- Gate the collector's package-database parse on source-database modification time so unchanged hosts skip parsing entirely, not just upload.
- Pin hash canonicalization (SHA-256 over sorted normalized package-identity fields, with volatile CycloneDX metadata excluded), prefix a 1-byte algorithm-version, recompute the hash server-side on every changed upload and flag mismatches, and force a full reconcile upload every Nth scan / M days so a stuck or poisoned hash cannot suppress inventory indefinitely.
- Maintain a local last-known-good inventory cache on the endpoint that serves unchanged-scan decisions and on-demand query commands.
- Store raw SBOM component payloads in durable object storage content-addressed by `artifact_hash`, deduplicated across hosts (golden-image dedup), with size limits and retention metadata; scan-specific provenance is stored as metadata outside the content-addressed bytes.
- Split durable storage into current-state and history: normalized current package/component rows live in regular CNPG tables for point lookups and device detail (replaced only for changed inventories, never rewritten for unchanged scans); historical changed scans and package add/remove events live in TimescaleDB hypertables with compression and retention policies; package diffs are computed server-side at ingest.
- Serve fleet rollups and membership ("how many hosts have nginx 1.24?", "which devices run coordinate X") from maintained current-count tables, the GIN-indexed current-state `SELECT`, standing-question result aggregates, and TimescaleDB continuous aggregates — never ad hoc `GROUP BY` scans over the live current-state tables, never an AGE traversal.
- Add a bounded on-demand live query path over the existing agent-gateway command bus: device-scoped queries answered from the local cache, and cohort/fleet queries dispatched through a bounded scatter-gather (bounded concurrency, hard cohort cap with SRQL/persisted fallback above it) over a per-command result topic, with COUNT/EXISTS and DETAIL response modes.
- Put a typed freshness verdict (fresh/stale/unknown plus age) on every live answer and a cohort coverage envelope (targeted/answered/offline/expired/pending) so partial or stale answers are never read as authoritative or complete.
- Treat on-demand queries as cache-first. Force-fresh-scan is optional, disabled by default, device-scoped only, and — when enabled — requires an explicit RBAC permission, a per-agent single-flight semaphore, and a per-partition rate limit.
- Add command-bus safety: typed inventory command types, dispatch capacity and rate enforcement for inventory commands, a `CommandResult` payload byte cap, and a hard rule that SBOM artifact bytes never traverse the command/result stream.
- Add ingest backpressure for correlated mass change: jittered upload scheduling plus a bounded ingest admission queue so a fleet-wide patch flip does not collapse the hash-gate win into a synchronized upload storm.
- Add cost/volume observability: upload-reason counters, changed-vs-unchanged ratio (hash-flapping detection), object-store bytes, current-row counts, and autovacuum/compression lag.
- Surface current inventory, freshness, scan provenance, device risk posture, and live/standing query results on devices/assets via SRQL/API and a device + cohort query UI.
- Keep endpoint collection disabled by default, policy controlled, bounded, and privacy-redacted; ship OS-package sources first with language-manifest, listening-service, and executable-metadata sources behind separate policy flags.
- Key all inventory entities to the canonical device identity (`ocsf_devices.uid`) — never a parallel inventory-only ID space — so `ocsf_events.device.uid` == `ocsf_devices` PK == AGE `Device.id` agree on one canonical string, which alert grouping, risk updates, and causaloid reasoning all depend on. `ocsf_devices.uid` is unchanged and gains no ordinal column.
- Model endpoint software as first-class ontology now (not reserved): a normalized `Package` entity keyed on a canonical PURL/CPE coordinate, `Device HAS_PACKAGE` as a CNPG current-state relation + SRQL projection (NOT a graph edge), and a feed-agnostic package-to-advisory coordinate-match interface (canonical PURL/CPE plus a `{package_manager, name, version, architecture}` fallback for feeds without PURL, e.g. Trivy). The endpoint side derives candidate CPE(s) per package (CycloneDX CPE is sparse for OS packages) so CPE-indexed feeds like VulnCheck NVD++ can match; CPE is a co-equal coordinate, but CPE matching is `vendor:product` + version-range — that range evaluation, PURL↔CPE mapping, and distro-backport false-positive handling are matcher-owned. This change owns the endpoint-side `Package` entity, device/package relation, and match input contract; the advisory feed, advisory-side `Package AFFECTED_BY CVE` population, CVSS scoring, and vulnerability matcher policy are owned by `add-cti-signal-coverage`, meeting at the canonical coordinate (host-scope endpoint findings kept distinct from image-scope scanner findings).
- Add a canonical-PURL invariant: compute `purl_canonical` server-side at ingest and make it the primary coordinate/dedup key (with the identity-tuple fallback), landed before `package_set_hash` locks PURL into the hash.
- Center on automation: server-computed package change events (`added`/`removed`/`version_changed`) and CVE-match vulnerability findings flow at ingest through the existing `CausalSignals`/event-writer seam into `ocsf_events`. Findings are OCSF Vulnerability Findings (`class_uid=2004`) keyed on `ocsf_devices.uid`, alert-eligible via `stateful_alert_rules` (`group_by: device`), northbound-automatable via the Ash `OcsfEvent.record` path (ticket/quarantine/webhook), and enrich device risk state via the `DeviceRiskReducer` (MAX-wins, ingestor-driven so inactive-device risk is never suppressed). The causal engine reads these (current state via SRQL, deltas via the event stream) to predict failure / score risk.
- Touch the AGE topology graph in exactly one bounded way: SET a ≤5-scalar per-device risk summary (`pkg_worst_severity`, `pkg_critical_count`, `pkg_kev_count`, `pkg_has_unpatched_rce`, `pkg_risk_summary_at`) on the EXISTING `Device` vertex. No `Package` vertices and no `HAS_PACKAGE`/`AFFECTED_BY` edges — at 100k hosts × ~1,500 packages those would be ~150M edges and would wreck the network-scale topology graph and the causal freeze/unfreeze cycle. Package membership stays relational + GIN-indexed.
- Build the `uid → u32` fleet-ordinal dictionary now (`platform.device_fleet_ordinals`, keyed on `ocsf_devices.uid`, never reused, tombstoned/reassigned on merge) — the only irreversible piece. Defer the roaring-bitmap inverted index itself (the rustler NIF, in-memory and rebuildable, reusing the `god_view_nif` pattern) to a hooked deferred section, built when an interactive cohort/drill-down consumer ships. The causal engine and the automation pipeline consume none of it; any render/verdict-layer intersection is a uid translation (`query_and_resolve_to_uids`), never a cross-space bitmap AND with god_view's ephemeral per-snapshot indices.
- Design the agent status heartbeat to carry operator-defined standing-question result counts so continuously-evaluated fleet predicates can feed the continuous aggregates without a later protocol change.

## Non-Goals
- Do not enable full package or filesystem inventory by default.
- Do not perform broad filesystem hashing.
- Model the endpoint-side software ontology now — the `Package` entity, `Device HAS_PACKAGE` (relational), and the coordinate-match input contract — but do NOT build the CVE/advisory feed, advisory-side `Package AFFECTED_BY CVE` population, matcher policy, or CVSS scoring engine; those remain `add-cti-signal-coverage`'s scope. The two changes meet at the canonical PURL/CPE coordinate.
- Do not introduce `Package` vertices or `HAS_PACKAGE`/`AFFECTED_BY` edges into the AGE topology graph; only a bounded per-device risk summary is SET on the existing `Device` vertex. Package membership is relational + GIN-indexed, never a graph traversal.
- Do not add a derived-ordinal column to `ocsf_devices`; the `u32` lives only in `device_fleet_ordinals` and the (deferred) in-memory index. `ocsf_devices.uid` is unchanged.
- Do not treat topology/god_view as the primary consumer; the primary consumers are alerts, northbound automation, device/service state enrichment, and the causal engine. god_view is one optional renderer.
- Do not build the roaring NIF in this slice (deferred until an interactive cohort/drill-down consumer ships); only the `device_fleet_ordinals` dictionary is built now.
- Do not replace Bumblebee exposure scanning; endpoint SBOM inventory complements it with durable package/component state.
- Do not implement a peer-to-peer or linear endpoint chain; use the existing agent-gateway unicast control stream and partitioning.
- Do not make Postgres the first stop for every unchanged package scan.
- Do not run ad hoc fleet-aggregate `GROUP BY` scans over the live current-state package tables; fleet rollups come from maintained current-count tables, standing-question result aggregates, TimescaleDB continuous aggregates, or bounded GIN-indexed membership `SELECT`s.
- Do not adopt a separate columnar engine (e.g. ClickHouse). Historical and analytical needs are served by TimescaleDB hypertables and continuous aggregates; DuckDB may be added later for ad-hoc analytics.
- Do not support fleet-wide force-fresh-scan; force-fresh is optional, device-scoped, and guarded.
- Do not carry SBOM artifact bytes over the agent command/result stream.

## Dependencies
- Agent configuration delivery must assign an endpoint inventory profile to a managed agent.
- Datasvc object uploads must keep enforcing bounded object size and storage limits, and support content-addressed reuse for canonical SBOM component payload bytes while scan-specific provenance remains separate metadata.
- The existing agent-gateway control stream and command bus must route on-demand inventory queries to connected agents without inbound connectivity to endpoints, and must support a bounded cohort scatter-gather with a per-command result topic.
- TimescaleDB must be available for endpoint inventory history hypertables, compression/retention policies, and continuous aggregates, degrading to plain tables where the extension is absent (matching existing `maybe_create_hypertable` conventions).
- This change adds an `endpoint_inventory.force_fresh_scan` permission to the RBAC catalog (`elixir/serviceradar_core/lib/serviceradar/identity/rbac/catalog.ex`, which has no endpoint-inventory entry today) to authorize guarded force-fresh-scan commands.
- Inventory must key to the canonical device identity (`ocsf_devices.uid`), not a parallel ID space; `ocsf_events.device.uid` == `ocsf_devices` PK == AGE `Device.id` is the single join key the automation thesis (alert `group_by` device, risk `UPDATE ... WHERE uid=`, causaloid reasoning) depends on. The `device_fleet_ordinals` `u32` is a derived dictionary (justified only by the deferred roaring index's 32-bit need) that references `ocsf_devices.uid`, survives merges (never reused), and is distinct from god_view's ephemeral per-snapshot index.
- The automation path depends on existing platform mechanisms it must extend: the `CausalSignals`/event-writer seam (needs an `inventory` domain + a vuln-finding branch + direct `device.uid` population), `stateful_alert_rules` (needs a device-uid grouping clause + explicit `evaluate_events` wiring from `CausalSignals`), `DeviceRiskReducer` (MAX-wins enrichment), and the Ash `OcsfEvent.record` northbound path.
- The causal engine consumes inventory through `EmbeddedSrql` over CNPG (current state + on-demand TimescaleDB aggregates + the bounded Device risk attributes via `graph_cypher`) plus the package change-event / finding stream via the `CausalSignals`/event-writer seam (`signals.causal.inventory.*` → `ocsf_events`). The inventory history hypertable MUST NOT be on the CDC allowlist (history is queried on-demand via SRQL, per the platform rule against CDC-ing TimescaleDB hypertables).
- The advisory feed, advisory-side `Package AFFECTED_BY CVE` population, vulnerability matcher policy, and CVSS scoring are owned by `add-cti-signal-coverage`; this change provides the endpoint-side `Package` entity, current device/package relation, and canonical coordinate input contract. Existing feeds (Trivy `trivy_findings` keyed by `(CVE, package_name)` without PURL and image-scoped; AlienVault OTX IP/CIDR-only today) inform the fallback and scope handling.
- Database schema changes must be implemented through Elixir migrations under `elixir/serviceradar_core/priv/repo/migrations/`.
