# Change: Refactor device identity reconciliation (DIRE) — stop identifier explosion, fix agent/Proxmox merging, restore the Proxmox connector

## Why

DIRE is failing at its core job in the live demo, and a multi-angle investigation (live CNPG forensics + full code reads of the reconciler, every ingestor, the agent registration path, and the web-ng read models; 23 root-cause findings adversarially verified against code AND live data) shows the failures are structural, not incidental:

1. **`platform.device_identifiers` has 12,291,808 rows (10.2 GB)**. 99.75% of the 12.19M `mac` rows are **comma-joined multi-MAC blobs stored as single "strong" identifiers** (avg length 191 chars, max 2,599; one value contains 68 MACs). The Go agent's Armis path returns the entire comma-separated `macAddress` field as the "primary MAC" (`go/pkg/agent/sync_runtime.go:1213-1216`) and `normalize_mac` (`identity_reconciler.ex:1844-1859`) never splits or validates, so every ordering/subset/re-roll variation of a device's MAC list mints a brand-new identifier row. The demo faker amplifies this by regenerating random "historical" MACs on every pod restart (unseeded `randInt`, `go/cmd/faker/main.go:1449-1457`; its PVC persistence fails on a permission error), adding ~44k rows per restart — but DIRE accretes **every** distinct value forever: no validation, no TTL, no per-device cap, no GC (`n_tup_del=0` for the table's lifetime).

2. **Agents are missing the lightning-bolt badge** because their device records were destroyed by an ongoing merge war. A 2026-06-04 register-time `identifier_conflict` merge keyed only on `agent_id` collapsed the k8s worker devices into one survivor; IP-alias states then "confirmed" 10.0.2.8–.12 onto that survivor, and `maybe_merge_ip_alias_device` (`identity_reconciler.ex:379-400`) + the sync ingestor's alias merge re-merge **unconditionally on bare IP match with no strong-identity guard** — producing a bidirectional merge oscillation (184 `ip_alias_conflict` audits, pairs re-merged 18–22×, still active). Net live state: 5 of 6 worker agents' `ocsf_agents.device_uid` point at one chimera device; the real host rows are tombstoned; the rows still visible in /devices are stale Proxmox duplicates with no agent link → no bolt. The device *show* page badge is dead code for everyone: it checks `ocsf_devices.agent_list`, which nothing in the Elixir pipeline ever writes (0 of 50,166 devices have it set).

3. **Agent and Proxmox records never merge — structurally.** Agent enrollment registers exactly one identifier (`agent_id`; `mac: nil` at `agent_gateway_sync.ex:184`); Proxmox-sourced devices carry only `integration_id` + `mac` and usually no IP. Hostname — the one attribute both sides share — is not a DIRE identifier type. Zero identifier overlap means a merge is never even attempted: `merge_audit` (1,487 rows) contains **zero** merges involving a Proxmox-identified device. The Proxmox `integration_id` format also churned twice in one day (name-keyed → MAC-keyed) duplicating every guest within the Proxmox source itself, and current plugin code mints a third incompatible format, guaranteeing a third duplicate generation on connector resume.

4. **The Proxmox connector is hard-down** (virtualization tables frozen 2026-05-09; plugin 100% failing since 2026-05-22 with "Proxmox API token is required" after plugin credentials migrated to credential-broker grants the inventory WASM plugin cannot consume — 33,042 grants issued, 0 consumed; compounded since 2026-06-09 by a stale artifact download token (401) and the bumblebee catalog staging failure deadlocking all agent config delivery, addressed on branch `fix/bumblebee-gateway-catalog-delivery`).

5. **This keeps happening.** 9+ DIRE fix proposals and 3 surgical cleanup migrations in 5 months; every pathology those migrations cleaned has regenerated in the live DB because the generators were never fixed. The scheduled reconciliation job that should self-heal duplicates has been dead since 2026-02-06 (`ng_job_schedules.last_enqueued_at`), and the original redesign's guardrail phases (drift metrics, 50k-cardinality e2e) were never started.

## What Changes

- **Identifier hygiene at the boundary**: split multi-value MAC fields, validate/normalize every identifier value (12-hex MACs, length caps), assign confidence from evidence (IEEE local bit) instead of hardcoding `strong`; apply uniformly across Go agent sync runtime and all Elixir ingestors.
- **Identifier lifecycle**: per-(device, type) cardinality caps, last-seen-based supersede/TTL for volatile identifier types, a GC job, and growth/cardinality telemetry with alerts. One-time data remediation purges the ~12.16M blob rows (~10 GB), test-artifact agents/devices, and poisoned alias states, and repairs agent↔device links.
- **Single canonical write path**: every ingestor resolves identity through `IdentityReconciler`; remove `SyncIngestor`'s parallel inline resolution (IP-fallback that overrides strong identifiers, batch-local collapse, trust-any-`sr:`-uid bypass), `MapperResultsIngestor`'s direct `Ash.create` device creation, and pre-minted-uid bypasses.
- **Merge stability**: strong-identity guards on alias merges (a confirmed IP alias may corroborate but never override a distinct `agent_id`), per-pair merge cooldown + oscillation breaker, canonical-alias (tombstone-resurrection-proof) lookups for deterministic UIDs, identifier rebinds always audited (no silent last-writer-wins repoint).
- **Agent identity first-class**: distinct connected agents resolve to distinct devices; periodic agent↔device link repair (not one-shot at hello); merges preserve per-agent linkage and `device_agent_availability`.
- **Cross-source bridging so agent and Proxmox records CAN merge**: agent enrollment registers host evidence (interface MACs, machine-id/hostname); hypervisor enrichment registers guest/host NIC MACs and normalized hostname as corroborating identifiers via DIRE; stable, versioned Proxmox `integration_id` format with migration of both legacy formats. (Builds on pending `add-proxmox-guest-network-identity`.)
- **Restore the Proxmox connector**: credential-broker grant resolution for inventory WASM plugins (or token material in materialized assignment params), artifact download token refresh, end-to-end validation against pve01–pve04 once config delivery is unblocked by `fix/bumblebee-gateway-catalog-delivery`.
- **Unify the agent badge read model**: list view and show page derive "is agent" from the same `ocsf_agents` linkage; remove or populate the dead `agent_list` path.
- **Demo faker correctness**: deterministic (seeded) historical MAC generation, fix PVC persistence permission failure so restarts stop minting new identity universes.
