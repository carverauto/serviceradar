## 6. Tests and benchmarks
- [x] 6.1 Parity. Two-axis parity proven: (score) `engine_score_matches_anomaly_core_zscore` — the edge verdict score equals `anomaly-core`'s `z_score` over the same window (edge math == central math, one shared crate); (key) `series_key_from_source_identity/1` parity tests (3.4b) — an edge verdict's `source_identity` re-keys to the byte-identical `series_key` the central extractor derives (SNMP if_index + sysmon excluded-tag cases). So an edge verdict and a central verdict for the same input agree on BOTH value and series identity.
- [x] 6.2 Edge resource benchmark — DONE on the Linux box (sr-test-pve04, 16-core x86_64, kernel 6.8). `examples/edge_bench.rs` (+ `//rust/anomaly-addon:edge_bench` bazel target) drives the verbatim `DetectorEngine` at a realistic per-host series count under `/usr/bin/time -v`. Results (single core): **2k series → 315k evals/s, 8.6 MB RSS; 5k → 313k evals/s, 16.7 MB; 10k → 309k evals/s, 30.2 MB.** Throughput is FLAT across series counts (linear scaling, no per-count penalty); RSS ≈ analytical 2.6 KiB/series + ~3 MB base. Against the add-on cgroup caps (`memory.max` 256 MB, `cpu.max` 50% of one core): 10k series = 30 MB = **8.5× memory headroom**; a 2k-series host needs ~133 evals/s vs 310k available = **~2300× CPU headroom**. (Run via a self-contained mini-workspace — anomaly-core + the engine, no proto/gRPC — since the box has no repo checkout.)
- [x] 6.3 Restart/re-warm — covered by the checkpoint unit tests: `checkpoint_round_trip_rewarms_baseline_and_counter` proves a reseeded baseline scores a spike IMMEDIATELY (warm, not cold → no refill false-positive storm) and the counter state resumes rating (not re-warmup); `checkpoint_skips_stale_series` proves a too-old baseline is dropped; `checkpoint_file_round_trip_atomic` proves the on-disk load/atomic-write/cold-start path. Full multi-process restart-under-load is a deploy-time check (needs the agent + go-plugin harness).
- [x] 6.4 N/A after §8 — the central anomaly durable lag/CPU comparison target no longer exists because the `ANALYSIS_METRICS_*` durables and central raw-stream analyzer were deleted. The measurable gate that remains is edge resource usage (§6.2) plus EventWriter ingest benchmarks in `fix-eventwriter-backpressure-hotpath`.
