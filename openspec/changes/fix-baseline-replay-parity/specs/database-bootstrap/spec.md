## ADDED Requirements

### Requirement: Baseline reproduces migration-produced data and TimescaleDB policy state
A database created from the schema baseline SHALL hold the same seed rows and the same
TimescaleDB compression settings, compression policies and retention policies as a database
created by replaying the same migrations. The baseline SHALL be generated from a replayed
database and SHALL carry that state itself, so no migration the baseline covers needs to run.
The generator SHALL refuse to produce a baseline when the replayed database holds TimescaleDB
state or rows it does not reproduce.

#### Scenario: Seed rows reach a fresh install
- **GIVEN** a migration covered by the baseline inserts default rows
- **WHEN** a fresh database is created from the baseline
- **THEN** those rows SHALL exist
- **AND** columns whose default is not immutable, such as generated ids, epochs and timestamps,
  SHALL take values generated by that installation

#### Scenario: Policy state reaches a fresh install
- **GIVEN** a migration covered by the baseline enables compression on a hypertable or adds a
  compression or retention policy
- **WHEN** a fresh database is created from the baseline
- **THEN** that hypertable SHALL have the same compression settings and policy jobs as on a
  replayed database

#### Scenario: A baseline missing covered state fails the freshness check
- **GIVEN** a covered migration inserts literal rows into a table, or configures compression or
  retention
- **AND** the baseline does not carry that state
- **WHEN** the baseline freshness check runs
- **THEN** it SHALL fail and name the table and migration
- **AND** it SHALL state how to regenerate the baseline

#### Scenario: Migration-enqueued jobs are not seed data
- **GIVEN** a covered migration enqueues a job that processes existing rows
- **WHEN** a fresh database is created from the baseline
- **THEN** the job SHALL NOT be enqueued
