OpenSpec · add-syslog-vendor-profiles

Vendor syslog becomes filterable fields

ServiceRadar already stores the raw syslog body. This proposal adds the vendor fields inside that body (interface, BGP peer, alarm, user) by turning the napalm-logs device profiles into installable Solution Packs. This pull request is the proposal. The matcher and the packs wait until the proposal is approved.

  • Base staging
  • napalm-logs 1f7b06f
  • 10 platforms · 109 messages · 133 fixtures
  • Apache-2.0

Goal

Now

A line is a log

Flowgger parses the header (RFC 3164, RFC 5424, ClearPass) and publishes GELF fields. Zen then runs passthrough, Coraza, strip-full-message, syslog severity, and CEF severity. The body stays text.

Wanted

The same log, with fields

A tenant installs the platform they run. A matching line keeps its body and gains attributes such as network.interface.name and syslog.event. An unmatched line is stored as it is today.

Constraint

One engine, both processes

The collector and core both compile rules through rust/zen-normalize. Collectors do not read the catalog database. A profile has to live inside the published logs.syslog bundle.

Worked example

Junos interface-down, from the napalm-logs corpus. The tag sits in the body, after the process name, so Flowgger’s application_name is mib2d and the tag is the first token of short_message.

How a pack reaches the collector

Where the rules live

The decision is which object carries a napalm-logs profile. Packs already distinguish stateful_alert_rule, event_rule, and zen_rule. No built-in pack ships a zen_rule today, and ZenRuleTemplates.compile/2 loads a static JSON file and ignores builder_config.

Proposal Use this

Template syslog_profile

One built-in pack per platform. Each pack installs one zen_rule named syslog_profile_<os>, subject logs.syslog, order 112. builder_config is the profile JSON. Compile embeds that JSON in a single custom node, syslog_profile, implemented once in rust/zen-normalize and registered from RuleSet::compile.

Cost: one new template branch, one custom node, and pack validation for that template. The reconciler, provenance columns, and bundle publisher stay as they are.

Rejected for 0.1.0

New pack kind

A resource kind syslog_profile with its own table. That repeats the Zen rule row, the exporter, and the publisher. Collectors would still need the compiled document in the bundle, so the new kind does not remove the engine work.

Rejected for 0.1.0

109 hand-written graphs

Each message becomes Zen expression nodes. The expression language has no capture-group replacement, compile/2 ignores builder_config, and 109 graphs are not a reviewable port of the YAML.

What a pack contains

Rule shape

kind: zen_rule
name: syslog_profile_junos
subject: logs.syslog
stream_name: events
format: json
template: syslog_profile
order: 112
builder_config: serviceradar.syslog.profile.v1

On a match

  • syslog.os, syslog.event, syslog.tag, syslog.profile, syslog.matched
  • Canonical keys such as network.bgp.peer.address and alarm.severity
  • syslog.fields and syslog.yang for the napalm mapping
  • Body, host, application name, and severity fields stay put

Match is tag-indexed, then a case-insensitive search. A single space in a line template matches a run of whitespace, the same rule napalm-logs uses. Transforms stay closed: upper, str, int, bgp_state_convert, bfd_state_convert, color_to_severity. Pack validation rejects any other transform, a pattern that does not compile, and nested unbounded repetition.

A compile error or a node error increments zen_syslog_profile_errors and leaves the log in place. A miss is not an error.

Requirements this change adds

syslog-vendor-normalization (new). Profile document, tag-indexed match, raw-prefix fallback, closed transforms, attributes beside the raw body, first match wins, errors do not drop the log, corpus equivalence with napalm-logs.

solution-packs-catalog (added only). Packs use the existing zen_rule kind, stay catalog entries until a tenant installs them, and fail validation on a bad profile.

observability-signals (added only). A match stays a log. Profile rules run after strip-full-message and before syslog severity. The active change improve-syslog-ingestion-fidelity still owns header detection, lossless fallback, and source_ip.

Implementation tasks

1. GeneratorRead the pinned YAML and the one Python profile. Emit serviceradar.syslog.profile.v1. Fail on an unknown transform or a capture with nowhere to land.
2. MatcherCustom node in rust/zen-normalize. Tag index, transforms, syslog.matched short-circuit, fail-open counter.
3. Template and packsCompile builder_config into the node. Ten catalog packs, order 112, napalm-logs credit in each README. Install and uninstall go through the existing reconciler. No tenant is seeded.
4. Corpus and docs133 fixtures plus a parsed-record test per platform, a collision test across all profiles, and updates to docs/docs/syslog.md and docs/docs/solution-packs.md.
5. Checksopenspec validate add-syslog-vendor-profiles --strict, then remote Bazel for //rust/zen-normalize:zen_normalize_test and the pack-manifest tests.

Failure and migration

Failure modes

  • Two installed packs match one line. First rule at order 112 wins. The corpus loads every profile and fails if two of them match one fixture.
  • A bad regex or transform never reaches the hot path. Pack validation rejects it.
  • A node error keeps the original record and counts zen_syslog_profile_errors.
  • Uninstall removes the rule from the bundle. Logs already stored keep the attributes they have.

Rollout

  1. Land the matcher and validation with no pack installed. Behavior stays today’s.
  2. Add the ten packs to the built-in catalog. Operators install the ones they run.
  3. Document the attribute keys.
  4. Rollback is uninstall. There is no new database write path.

Settled for version 0.1.0

One pack per platform

A Junos site does not carry the Fortinet regexes. A pack has no pack-to-pack dependency, so a combined pack would be a later catalog entry, not a change to this design.

Fortinet traffic stays a log

FORWARD_TRAFFIC and LOCAL_TRAFFIC land as log attributes. Feeding them into the flow pipeline is outside this change.

This pull request stops at the proposal

openspec validate add-syslog-vendor-profiles --strict passed on the change. Tasks in tasks.md are unchecked. Implementation starts after the proposal is approved.
